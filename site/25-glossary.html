附录 A 术语、阅读地图与自检答案

术语表

术语 含义与注意点
Harness 模型周围的执行系统，负责上下文、工具与运行状态
Agent loop 在模型请求、工具结果和继续决策之间循环
Session / thread 长期会话容器；两个项目同名类型不一定兼容
Turn 必须结合项目定义理解，可能指用户回合或单次助手响应阶段
Step 本书通常指一次模型请求及其工具处理
Attempt 一次实际尝试，失败尝试不一定进入有效模型历史
Tool schema 模型参数的结构约束，不等于业务正确或执行授权
Provider / adapter 把统一请求与供应商协议连接起来的实现
Projection 从持久事实推导某个消费者需要的状态
Compaction 缩减模型工作上下文，通常需要摘要与边界元数据
Checkpoint 执行器恢复状态的检查点，不能用自然语言摘要替代
Replay 从已有记录重建或重执行；两种含义必须区分
Idempotency 重复相同业务请求不重复产生效果，需要实际服务参与
Approval 对特定行动和权限范围的允许，不是无限授权
Sandbox 对真实资源访问施加限制的执行环境机制
Scope 注册或路由的逻辑范围，不自动形成操作系统安全隔离
Disposer 撤销注册或释放资源的生命周期操作
Steering 在当前工作过程中进入的纠正或补充输入
Follow-up 按框架规则排在当前工作之后处理的输入
Outcome unknown 行动可能发生但结果不能确认，需要核验
Code mode / PTC 用程序组织工具调用；底层工具仍需要授权和结果管理
Worktree 独立工作目录机制，不等同于完整运行环境隔离

四条源码阅读路线

Codex：从回合执行进入步骤上下文，再看工具计划、路由、公共编排和并发运行时，最后看进程管理、压缩与历史重建。阅读时区分 core 内部状态、rollout 记录及 app-server 协议。C01C02C11C03C05C06C07C09C15

DeepSeek Harness：先读架构文档和 Cordis primer，再追踪 agent 的请求准备、工具调度、流结算与 session 投影，之后看代际迁移和子代理 provider。服务定义、provider、consumer 必须一起确认。D01D16D02D03D04D07D11D13

Pi：先读 agent-core 类型与循环，再看 AgentSession、SessionManager、编辑工具和扩展 runner；需要持久任务时另读 durable。不要将 durable 的 replay 政策归给普通内存循环。P02P01P04P05P07P10P12

Claude Code：先核对包版本与 map，再读 query、Tool、工具执行器、权限管线、压缩与会话记录链。遇到特性条件时，把“有实现”与“当前启用”分开记录。A01A02A03A04A05A06A07A10

十个自检问题与答案

  1. 工具参数通过 schema，是否可以直接执行？不能，还需要语义校验、授权和环境限制。
  2. 模型生成了助手文字，用户任务是否结束？不一定，还可能有工具、排队输入和停止钩子。
  3. 工具结果按顺序提交，外部副作用是否也按顺序发生？不一定，并发执行与提交是不同时间线。
  4. 点击停止能否证明没有写入？不能，需要看派发位置、工具取消语义与实际结果。
  5. 日志有 fsync，是否获得外部动作恰好一次？不能，本地日志不控制远程服务事务。
  6. 会话分支回退是否回滚代码？不能自动推导，工作区变更需要独立机制。
  7. 压缩摘要能否替代执行检查点？不能，摘要服务模型理解，检查点服务执行恢复。
  8. 进度节点是否应全部进入会话事实？不必，临时展示与语义记录有不同用途。
  9. Source map 文件一致能否证明所有分支已发布启用？不能，还要考虑来源、构建与门控。
  10. 增加 agent 数是否必然改善任务结果？不能，整合、冲突和成本都需要真实评测。

推荐的个人研究记录

每次源码研究保存五项内容：快照身份、问题描述、实际调用链、失败路径和仍待验证的结论。记录“未做真实 API 测试”比省略验证范围更有帮助。发现与本书不符时，先比较提交号，再判断是实现变化、入口差异还是分析错误。

书中未复印上游长段源码。读者可通过下一附录的固定提交链接定位开源实现；Claude Code 部分需要使用自行合法取得的同版本材料和哈希核对。链接失效时，完整提交号、相对路径与文件哈希仍可用于识别研究对象。
