第 15 章 Claude Code：先确定材料能证明什么

这份目录不是一个普通开源仓库

ccsource 同时保存发布包、提取源码、压缩包和已有分析书稿。本书选择 package 下的发布包元数据及 src-extracted/src 中与运行框架直接有关的文件作为研究对象。包名是 @anthropic-ai/claude-code，声明版本 2.1.88。其许可证声明与前三个开源项目不同。A01A15

书中只发布原创分析、相对路径、定位信息和文件哈希，不把发布包、source map 或提取源码复制进书籍仓库。源码所有权与本书分析文字的许可也分别说明。这个做法同时让公开仓库保持小巧，并避免把一个研究项目变成原始材料镜像。

Source map 校验解决了哪个问题

source map 不只有压缩代码位置映射，还可能包含 sourcesContent。该包的 map 提供源路径与嵌入文本。研究脚本为每个被引用的提取文件找到对应嵌入条目，并逐字节语义上的文本一致比较，同时保存原文件 SHA-256。A02

这个检查证明“本书读取的提取文件与本地 map 嵌入文本一致”。它不证明包一定来自官方分发，也不证明所有文本都对应当前启用分支。后者还受到构建条件、特性门控和运行配置影响。因此书中使用“该发布包可见实现”这样的表述，避免把静态发现直接扩大为所有用户都可用的产品能力。

Query 是最值得先读的路径

query.ts 通过异步生成器向调用者提供消息与事件。外层 query 委托 queryLoop，内部以显式 state 管理消息、工具上下文、压缩跟踪、输出限制恢复和轮次数等信息。每次循环形成实际请求，消费模型流，然后执行工具，决定后续状态。A03

异步生成器适合逐步暴露进展，但也有自己的生命周期：消费者停止迭代、异常抛出与正常 return 不是一回事。清理和后置动作要覆盖相应退出方式。只看正常 yield 路径会漏掉中断时的行为。

显式状态减少递归歧义

该快照把跨迭代状态集中到一个对象，在不同继续分支更新。好处是避免多个局部变量在复杂恢复路径中部分更新、部分保留。代价是必须明确每个字段何时重置，例如输出长度恢复计数和压缩尝试状态不能在所有分支无差别继承。A03

修复案例里，一次模型响应因为输出过长失败，框架需要决定增大输出预算、压缩还是终止。这个决策不等于开启一个全新用户任务；原来的目标、已发生工具结果和恢复计数仍需正确关联。

产品功能为什么集中出现在循环周围

可见循环接入相关记忆预取、技能发现、工具结果预算和压缩等机制。它们说明运行框架不只执行工具，还管理模型请求中哪些信息值得出现、何时提前准备可以减少等待。A03

不过，预取存在并不证明结果一定进入上下文，特性分支存在也不证明默认启用。分析一个实际用户问题时，需要继续核对门控值、调用源和最终消息组装位置。本书把这些路径作为架构观察，不对未运行验证的分支作可用性承诺。

阅读提取源码的实践规则

遇到同名工具先找主名称与别名，遇到实验功能先找 feature 条件，遇到可疑“服务端机制”先确认是否只是一条客户端注释。提取源码中引用的内部模块、构建工具与专有服务并不自动随材料齐全；无法原样构建，不等于局部执行逻辑不可分析，但必须限制结论范围。

练习：看到某函数参数有 remote，能否断言它是当前公开功能？检查要点是不能，需要确认构建分支、入口可达性、配置与实际服务。名字是线索，不是完整证据。
