序言：从会回答问题到能完成工程任务

一个编程智能体收到“修复路径校验漏洞”的任务后，可能先搜索代码，读取实现和测试，修改一处条件，运行测试，再根据失败信息继续修改。界面里只有几次自然语言往返，底层却发生了模型请求、工具调用、权限判定、子进程管理、历史更新和状态持久化。只研究提示词，很难解释它为什么有时能持续工作几十分钟，有时却会在一次断线后重复执行操作。

本书研究这层执行系统，也就是 harness。这里把它译为“智能体运行框架”：它围绕模型组织上下文、调度工具、记录事实、处理取消和恢复，把一次概率性的输出接到真实的软件工程环境上。模型决定下一步提出什么行动，运行框架决定这个行动能否执行、执行的结果如何进入下一次推理，以及发生故障后还能相信什么。

我们从四份本地材料出发。Codex 展示 Rust 核心、明确的工具路由、审批与沙箱编排，以及结构化协议；DeepSeek Harness 展示以 Cordis 组织的插件体系、可替换能力和日志驱动的上下文；Pi 展示模型访问、循环内核、编程应用和实验性持久运行框架的分层；ccsource 展示 Claude Code 2.1.88 发布包内可以通过 source map 核验的执行与产品机制。这四份材料并不处在相同的版本阶段，也不提供相同的可见范围。书中的比较因此围绕具体机制展开，不给出脱离实验条件的“最强智能体”排名。

本书承诺的分析深度

每个项目都沿着“输入进入—请求形成—响应消费—工具执行—结果提交—继续或停止”的路径分析。读者不仅会看到目录说明，还会看到设计约束、错误路径和一个设计换来的收益与代价。讨论并发时，我们追踪哪个顺序可以变化、哪个顺序必须稳定；讨论持久化时，我们区分日志写入、历史重建和外部副作用；讨论安全时，我们区分模型看到的指令与执行器真正拥有的权限。

全书使用统一的源码编号，例如C01代表 Codex 回合执行文件，D03代表 DeepSeek Harness 工具调度文件。附录提供文件相对路径、定位符、行号、SHA-256，以及开源项目固定提交上的链接。Claude Code 提取文件附带与发布包内 sourcesContent 的一致性校验结果。编号用来缩短正文，不意味着一个文件可以证明围绕它提出的所有工程建议。

正文把证据分为三类：“源码事实”是本地快照能够直接支持的行为；“工程解释”说明为什么这类实现能解决某个问题；“设计建议”是作者为自建系统提出的方案。特别是事务、幂等和评测章节，不能把建议误认为四个项目都已经提供的保证。

阅读路线

如果你第一次开发智能体，先读第 1、2 章建立术语，再读 Pi 篇，最后完成实验。已有运行框架的工程师可以从第 19 章的横向比较进入，再回到项目篇追踪依据。负责平台、安全或可靠性的读者可以重点阅读权限、恢复、评测和发布章节。

源码细读路线则从本书证据索引进入。先定位章节给出的函数，再沿真实调用关系寻找接口、实现与测试。不要把历史教程里熟悉的文件名当作当前事实。例如本次 Codex 快照的主要回合逻辑位于 core/src/session/turn.rs，而不是许多旧文章引用的 core/src/codex.rs。目录移动本身不改变概念，但会让未经核验的分析失去可信度。C01

版本与方法边界

本版分析日期为 2026-10-30，依据用户指定目录中的快照，不主动更新上游仓库。三个 Git 仓库的完整提交号和本地状态记录在附录与 research/sources.json 中。已有书稿仅作为材料类型识别的线索，本书没有把它们拼接为新书，也没有把未跟踪的生成文档当作实现依据。

这是一部静态源码分析与可运行机制实验相结合的书。我们没有使用真实模型对四个产品进行统一性能评测，没有构建全部上游项目，也没有据此证明任一产品在生产环境绝对安全。书中的实验使用本仓库自行编写的确定性驱动，作用是验证日志、取消和恢复的语义。读者可以在没有 API 密钥的情况下复现这些结果。

在线版与 EPUB 由同一组章节构建。在线版适合检索和跳转源码，EPUB 适合连续阅读；两者共享版本、章节编号和证据索引。全书分析文字与实验代码均在仓库中提供，便于修订和复核。
