第 13 章 上下文构造：把窗口当作有预算的工作集

上下文不是 messages 的无限追加

一次请求包括系统规则、任务、工具声明、近期对话、读取证据、压缩摘要和运行事实。各部分重要性、有效期与可裁剪程度不同。推荐 ContextBuilder 接收带元数据的片段，而不是一开始就把所有内容混成字符串。

ContextItem {
  id, source, role, content_ref, estimated_tokens,
  priority, pinned, validity, trust_level,
  evidence_refs[], dependency_group?
}

validity 可以是当前 step、当前 turn、工作区版本或长期规则。dependency_group 把工具调用与结果放在一起，防止裁剪一半。

预算公式与选择顺序

设模型窗口 W，计划输出 O，协议和估计误差余量 M，则输入预算为 B = W − O − M。工具声明也消耗 B。先扣不可裁剪规则、当前用户输入和必要协议，再给检索、近期历史和摘要分配容量。

假设仅作示意的 W=128000、O=8000、M=4000，则 B=116000。若强制内容占 20000，剩余才是 96000；不能再给每个模块各自“最多 100000”而不汇总。实际 tokenizer 与 provider 的计费字段可能不同，使用真实用量反馈修正估计。

选择算法应该可解释

先加入 pinned 内容，若已超限则明确失败，不能丢掉系统限制继续请求。其余片段按必要性、相关性、新鲜度和大小考虑，满足依赖组后再加入。可用效用/成本作为启发式，但用户最新约束不应只因 token 多就输给短片段。

每次构造生成 receipt：选入哪些 id、裁剪哪些、原因、估计与实际预算、投影版本。这样调试时能回答“模型为什么没看到那条错误”。只记录最终总 token 数，无法定位上下文丢失。

运行事实需要更新而非重复堆叠

cwd、权限模式、当前分支、可用工具和进程状态会变化。用有来源的 runtime facts 更新相应逻辑位置或创建可重建的新版本，避免每轮重复注入互相矛盾的“当前状态”。DeepSeek 将运行上下文纳入日志和冻结请求，Codex 的步骤上下文则提供另一种快照思路。D02C02

外部事实也会过期。上轮读取的文件在编辑后不能继续被当作当前实现；测试证据应绑定当时的文件或工作区版本。模型可以看到旧事实作为历史，但展示标签必须说明它属于过去。

工具历史要保持协议完整

裁剪时把 assistant tool call 与相应 result 作为原子单元；若多个调用属于一个 provider 消息，按协议保持分组。不能保留结果而删除调用，也不能保留已执行调用却不说明结果。对大结果可替换为摘要与产物引用，但要保留 call_id 和状态。

Pi 的 transformContext 与 convertToLlm 发生在模型边界，提醒我们区分应用消息选择和供应商消息转换。前者决定内容，后者决定表达，两者都可能有损，应独立测试。P01P02

Prompt cache 与正确性的优先关系

稳定前缀、确定工具顺序和可追加更新有利于缓存。不要为提高 cache hit 把过期权限、旧工具 schema 或失效文件保留成当前事实。请求若路由到不支持中途更新的模型，需要重新形成完整正确前缀。

缓存身份与会话身份也不相同。将一个缓存键复用于不同用户或不同权限上下文，可能造成隔离错误；应由模型 adapter 根据明确规则处理，不让 UI 随便传一个 session string 就控制所有缓存。

验收方法

构造几乎占满窗口的历史，检查最新用户限制仍在、工具调用结果仍配对、过期文件不伪装成当前证据、超限 pinned 内容明确报错。记录模型真实接收的请求并与 receipt 比较；不要仅检查 ContextBuilder 内部数组，adapter 最后还可能改写它。
