附录 C 版本、构建与实现边界

第二版的定位

本次增订为 2.1.0，研究日期沿用 2026-10-30 的固定源码快照。第一版按项目分别分析；第二版按 AI Coding Agent 的设计与实现问题重写，补充核心接口、状态机、数据结构、算法、故障时序和可运行内核。2.1.0 增补源码驱动的任务流程、Tool/Skill/MCP 机制、四套压缩实现与取舍比较，并把证据索引扩展至 85 个文件。旧版 EPUB 仍可在对应历史 Release 获取。

源码与可运行实现的关系

四个项目提供机制参考，编号在附录 B 定位。本书接口、参考代码、图示和设计建议均为独立编写；没有上传 Claude Code 原始发布包、source map 或提取源码。对照 source map 证明本地引用文本一致，不等于认证发行来源或证明所有特性分支启用。

reference_agent 实现模型驱动循环、工具表、简单 schema、短时授权绑定、SQLite 调用与事件提交、有界批次调度、文件前置条件、固定验证与保守恢复。labs 独立演示 JSONL 与后置核对。它们使用标准库和可丢弃工作区。

以下内容给出设计方案，尚非本仓库完整生产实现：真实模型供应商的流式 SDK、操作系统沙箱、远程 worker、分布式 fencing、持久交互审批、通用压缩器、LSP、MCP、任意 shell、完整 IDE 与多 agent 平台。正文在对应章节解释升级条件和验收场景。

构建与验证

python3 scripts/build.py
python3 scripts/check.py
python3 -m unittest reference_agent.test_core -v
python3 -m unittest discover -s labs -v
node --check web/reader.js

构建需要 Python 3.9+ 和 Pandoc 3.12.1。EPUBCheck 5.4.0 需要 Java。在线版与 EPUB 共享章节；构建不依赖上游四个目录，只有重新采集证据才需运行 snapshot 脚本。

出版结构检查验证包、资源、导航和内部链接；机制测试验证本仓库程序；浏览器检查验证阅读器；真实模型任务质量、安全隔离与上游运行均是独立范围。验证报告不扩大解释。

维护方法

变更模型协议时更新流 fixture，变更工具时更新校验与权限测试，变更存储时执行故障与迁移测试，变更上下文时验证约束和证据仍存在。升级上游后重新核对源码，不只替换提交号。

书籍也按同样原则发布：固定版本、保留来源、构建同一内容、验证后部署。反馈最好提供章节、设计问题、证据编号和复现条件，便于针对真实机制修订。
